\title{Simulation-Grouped Per-Class QoS Prediction and SLA-Aware Bandwidth Allocation for SD-WAN}

\author{\IEEEauthorblockN{Radhika (Rishiv) Shitlani}
\IEEEauthorblockA{School of Computer Science\\
University of Galway, Galway, Ireland}}

\begin{document}

\maketitle

\begin{abstract}
Software-defined wide area networks (SD-WANs) require class-aware quality-of-service (QoS) decisions, yet a strong global prediction score can conceal poor performance for best-effort traffic. This paper studies per-flow delay prediction and service-level-agreement (SLA) violation detection using 29,280 flow records from 400 BNNetSimulator runs spanning Gold, Silver, and Bronze traffic under three scheduling policies. An XGBoost regressor is evaluated with five-fold cross-validation grouped by simulation identifier, ensuring that all flows from a simulator run remain in one fold. The grouped protocol achieves an overall log-delay $R^2$ of 0.747; class-specific $R^2$ values are 0.907, 0.898, and 0.680 for Gold, Silver, and Bronze, respectively. Corresponding SLA-violation F1 scores are 0.940, 0.680, and 0.554. A row-wise split gives a higher overall $R^2$ of 0.766, quantifying the optimism caused by sharing simulation contexts across folds. Under the grouped protocol, 90th-percentile delay is only moderately predictable ($R^2=0.293$ overall) and jitter is not predictable ($R^2=-0.040$). Finally, a model-assisted weighted fair queueing recommender selects 60/30/10 for Gold/Silver/Bronze under the tested mean-delay thresholds. The results show that grouped, per-class evaluation is necessary for credible QoS prediction and bounded allocation support.
\end{abstract}

\begin{IEEEkeywords}
SD-WAN, quality of service, machine learning, XGBoost, grouped cross-validation, SLA prediction, bandwidth allocation

\section{Introduction}

Software-defined wide area networking (SD-WAN) separates network control from forwarding and enables centrally managed routing and QoS policies across heterogeneous links. In practice, however, many policies remain static or reactive: an operator changes queue weights or routes after congestion has already affected users. Predicting QoS before an SLA breach could enable proactive control, but operational usefulness depends on more than one aggregate regression score. Gold, Silver, and Bronze traffic have different priorities, delay distributions, and costs of error. A model that performs well globally can still be unreliable for the class most exposed to congestion.

Prior work has used machine learning for virtual-network-function scaling~\cite{rahman2019autoscaling}, application-aware routing~\cite{zheng2022applicationaware}, and reinforcement-learning-based traffic engineering~\cite{dinh2024safeloadbalancing,chen2025mteal}. Other studies optimise SD-WAN routes and queueing policies from measured QoS~\cite{quang2022routing,quang2023globalqos}. These approaches demonstrate the value of predictive or adaptive control, but they do not directly establish how accurately continuous delay and SLA violations can be predicted for differentiated traffic classes using a compact, reproducible feature set.

A second concern is evaluation leakage. A packet-level simulation produces many flow rows from the same network run. Randomly splitting individual rows can place flows from one simulation in both training and validation data. Although the simulation identifier is not an input feature, shared topology, load, and scheduler conditions may still make the validation task artificially familiar. This paper therefore treats the simulation run, rather than the flow row, as the resampling unit.

The contributions are threefold:
\begin{itemize}
    \item a reproducible per-class delay-prediction study using 29,280 flows from 400 BNNetSimulator runs;
    \item a simulation-grouped evaluation reporting both regression and SLA-trigger performance separately for Gold, Silver, and Bronze traffic, with row-wise cross-validation retained only as a sensitivity comparison; and
    \item an offline, model-assisted weighted fair queueing (WFQ) recommender that ranks candidate allocations under class-dependent mean-delay thresholds.
\end{itemize}

\section{Related Work}

Machine learning has been applied to several adjacent network-management tasks. Rahman \emph{et al.} predicted scaling requirements for virtual network functions~\cite{rahman2019autoscaling}, while Zheng \emph{et al.} combined traffic classification with QoS-aware routing~\cite{zheng2022applicationaware}. For SD-WAN specifically, Quang \emph{et al.} formulated joint routing and QoS policy optimisation~\cite{quang2022routing} and later incorporated passive available-bandwidth estimation into a two-loop controller~\cite{quang2023globalqos}. Recent work also explores safe deep reinforcement learning~\cite{dinh2024safeloadbalancing} and multi-objective graph-based traffic engineering~\cite{chen2025mteal}.

Network simulators and learned network models provide a reproducible alternative when labelled enterprise telemetry is unavailable. BNNetSimulator generates packet-level data compatible with the modelling methodology underlying RouteNet-Fermi~\cite{bnnupc2023bnnetsimulator,ferriolgalmes2022routenetfermi}. The present study uses it for a narrower question: whether static configuration and path features support reliable, class-specific QoS prediction and a simple allocation decision. XGBoost is selected as the main model because boosted trees remain strong on small-to-medium tabular datasets~\cite{grinsztajn2022trees,shwartzziv2022tabular}, while retaining comparatively low training cost and feature-level interpretability.

\section{Methodology}

\subsection{Dataset and QoS Classes}

The dataset was generated with the official BNNetSimulator container~\cite{bnnupc2023bnnetsimulator}. It contains 29,280 source-destination flow records from 400 simulations, with 30--132 flows per run. Traffic is divided into Gold (4,592 rows), Silver (8,991), and Bronze (15,697). Gold has the highest priority, Silver represents interactive traffic, and Bronze is best effort. The experiments cover strict priority, WFQ, and deficit round robin scheduling within four scenarios: fixed WFQ, random WFQ profiles, mixed policies with skewed class proportions, and mixed policies with equal proportions. Loads are light to moderate; consequently, the results should not be interpreted as a stress-test of a saturated production network.

Each input row contains traffic class, offered bandwidth, traffic distribution, route length, network size, maximum average load, link bandwidth, scheduling policy, class queue weight, and minimum class weight. The target is the natural logarithm of average delay in seconds. Delay, jitter, packet loss, delay percentiles, achieved bandwidth, scenario label, and simulation identifier are excluded from the feature matrix. Numeric missing values are median-imputed and categorical variables are one-hot encoded inside each training fold.

\subsection{Prediction and Grouped Evaluation}

The primary regressor is XGBoost with 200 trees, depth four, learning rate 0.05, row subsampling 0.9, and feature subsampling 0.9. Predictions are converted back to milliseconds for interpretation. Performance is measured using mean absolute error (MAE) on the delay scale and $R^2$ on log delay.

Five-fold GroupKFold cross-validation is used with \emph{simulation\_id} as the group. Thus, no simulation contributes flows to both training and validation in a fold. For sensitivity analysis, the same model is also evaluated using shuffled row-wise five-fold cross-validation. Preprocessing and model fitting occur independently inside every fold.

Continuous delay predictions are converted into SLA-violation triggers using thresholds of 30, 50, and 60 ms for Gold, Silver, and Bronze. Precision measures the trustworthiness of a trigger, while recall measures the fraction of actual violations detected. F1 summarises their balance. The Bronze threshold was selected in an exploratory sweep; it is not claimed as a universal operational SLA.

The same grouped folds and leakage-safe feature exclusions are used in secondary regressions for 90th-percentile delay and jitter. These targets are evaluated on their native scales because the operational question concerns absolute milliseconds. Negative $R^2$ indicates that predictions generalise worse than the validation-fold mean.

\subsection{Allocation Recommender}

After grouped validation, a final XGBoost surrogate is fitted on all available rows. Five WFQ profiles are evaluated: 60/30/10, 50/40/10, 33/33/34, 25/65/10, and 80/15/5, where values denote Gold/Silver/Bronze queue weights. For each profile, the scheduler and weight features are changed, predicted delays are aggregated by class, and feasibility is checked against the same 30/50/60-ms mean-delay limits. Feasible profiles are ranked by a priority-weighted normalised delay score,
\begin{equation}
S=3\frac{d_G}{30}+2\frac{d_S}{50}+\frac{d_B}{60},
\end{equation}
where $d_G$, $d_S$, and $d_B$ are predicted class means in milliseconds. This is an offline what-if analysis, not a causal guarantee: profile changes are not replayed through the simulator.

\subsection{Reproducibility}

The data-generation, preprocessing, grouped evaluation, plotting, and recommendation stages are implemented as separate Python scripts. Randomised estimators use seed 42, and every reported prediction metric is calculated from out-of-fold rows rather than from training predictions. The grouped evaluator also records the fold unit explicitly in its output artifact, reducing the risk that row-wise and run-wise results are mixed during reporting. The generated dataset, experiment scripts, and result tables are available in the project repository. A permanent archival identifier will be added to the camera-ready paper.

\section{Results}

\subsection{Per-Class Delay and SLA Prediction}

Table~\ref{tab:grouped} reports the primary grouped results. Overall $R^2$ is 0.747 with a delay-scale MAE of 13.19 ms. Performance is strongly class-dependent. Gold and Silver are predicted accurately ($R^2=0.907$ and 0.898), whereas Bronze falls to 0.680 and its MAE rises to 21.57 ms. The pattern is operationally plausible: protected traffic is governed more strongly by stable topology and scheduler configuration, while best-effort delay depends on transient contention that the static inputs do not observe.

\subsection{Effect of Grouping by Simulation}

Table~\ref{tab:protocol} and Fig.~\ref{fig:sensitivity} compare the grouped protocol with a shuffled row-wise split. Grouping reduces overall $R^2$ from 0.766 to 0.747. The largest class-level reduction is for Bronze (0.704 to 0.680); its SLA F1 decreases from 0.592 to 0.554. Gold remains stable. The result indicates modest rather than catastrophic leakage, but it is large enough to affect claims about generalisation and therefore justifies simulation-level grouping.

\subsection{Tail Delay and Jitter}

Table~\ref{tab:secondary} applies the grouped protocol to two secondary QoS targets. Tail delay is less predictable than average delay: overall $R^2$ is 0.293, with Gold and Silver reaching 0.550 and 0.490, while Bronze falls to 0.269. The corresponding Bronze MAE is 51.81 ms, consistent with rare contention events dominating the upper tail.

Jitter does not generalise from the static feature set. Overall $R^2$ is $-0.040$, and every class is negative. Gold and Silver have small absolute MAE but extremely low within-class variance, so modest errors are worse than simply predicting the validation-fold mean. These results sharpen the observability boundary: configuration and path features describe mean delay, partially describe tail delay, and do not describe moment-to-moment delay variation.

The recommender is deliberately bounded. If no candidate meets the thresholds, it can return an infeasibility signal rather than silently applying the least-bad policy. \section{Discussion and Limitations}

The central finding is not simply that delay is predictable; it is that predictability depends on traffic class, target, and validation design. Route length, network size, and class encode stable structure and explain protected mean delay well. Bronze is served after higher-priority traffic and is more sensitive to unobserved bursts and queue occupancy. The collapse on jitter confirms that increasing model complexity cannot recover information absent from the features.

Several limitations constrain the claims. First, the data are simulator-generated and cover a light-to-moderate load regime. Grouped folds test unseen runs from the same generator, not transfer to enterprise SD-WANs. Second, the feature set is static. Telemetry such as instantaneous queue occupancy, arrival-rate windows, and recent loss would be necessary to model transient behaviour. Third, the SLA thresholds are experimental operating points rather than contractual values. Fourth, the allocation recommender edits model inputs without rerunning the network, so it provides candidate screening rather than causal validation. Future work should repeat every model comparison under grouped outer folds, replay recommended profiles in BNNetSimulator, evaluate heavier congestion, and validate on controller telemetry.

\section{Conclusion}

This paper presented a simulation-grouped, per-class evaluation of QoS prediction for SD-WAN-like networks. XGBoost generalises well to unseen simulation runs for Gold and Silver mean delay but is less reliable for Bronze and does not generalise for jitter. Row-wise cross-validation overstates performance, confirming that the simulation run must be the evaluation unit. A WFQ recommender demonstrates how the validated model can rank candidate allocations while retaining explicit feasibility checks. The broader implication is that trustworthy AI-assisted QoS control requires class-aware metrics, group-safe validation, and honest bounds on what static network features can support.
